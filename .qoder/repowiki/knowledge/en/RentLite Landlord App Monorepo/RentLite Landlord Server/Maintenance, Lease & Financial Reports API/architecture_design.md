Three sibling Express `Router` modules (`maintenance.ts`, `leases.ts`, `reports.ts`) each mount an `authMiddleware`-protected namespace under `/api/maintenance`, `/api/leases`, and `/api/reports`. Each file is self-contained: it imports shared Drizzle ORM `db` and schema definitions from `../db/*`, applies Zod schemas for request validation, and performs in-memory filtering by the authenticated user's property IDs to enforce multi-tenant isolation. Business side-effects are co-located with routes — e.g., creating a lease sets the unit status to `occupied`, while terminating/expiring a lease resets it to `vacant`; completing a maintenance request timestamps `completedAt`. Report endpoints aggregate `payment`, `expense`, `unit`, and `property` tables entirely in memory after fetching full datasets, producing monthly cashflow, per-property Schedule E line-item summaries mapped via a `SCHEDULE_E_LINES` constant, and quarterly/yearly P&L statements.
