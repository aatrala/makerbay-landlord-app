Each file defines an independent Express `Router` mounted under `/api/properties`, `/api/tenants`, and `/api/units`. All routes are protected by a shared `authMiddleware` from `../auth/middleware.js` that injects `userId` into the request. Handlers read tenant-scoped data via Drizzle ORM (`db.query.*`) using `eq`/`and` filters scoped to `userId`, ensuring multi-tenant isolation at the query level. Input is validated with per-resource Zod schemas (`createPropertySchema`, `tenantSchema`, `createUnitSchema`) and their `.partial()` variants for updates; validation failures return a uniform `{ message, code: 'VALIDATION', details }` payload. Cross-entity relationships are enforced inline — e.g., creating a property auto-inserts `unitCount` rows into the `unit` table, and unit mutations verify ownership of the referenced `propertyId`. The module exports each router as a named export (`propertiesRouter`, `tenantsRouter`, `unitsRouter`) for mounting by the application's top-level router.
