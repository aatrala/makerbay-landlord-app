Three sibling Express Router modules (`payments.ts`, `expenses.ts`, `vendors.ts`) each define a resource-specific REST API mounted under `/api/payments`, `/api/expenses`, `/api/vendors`. Every route is guarded by the shared `authMiddleware` from `../auth/middleware.js`, which injects `userId` into the request. Data access uses Drizzle ORM against tables defined in `../db/schema.js` (`payment`, `expense`, `vendor`, plus related `unit`, `property`, `tenant`). Input validation is enforced per-route via Zod schemas (`paymentSchema`, `expenseSchema`, `vendorSchema`), with partial schemas used for update endpoints. Ownership scoping is applied at query time: payments and expenses are filtered to units/properties owned by the authenticated user, while vendors are directly scoped by `userId`. The payments module additionally exposes a `/summary` endpoint that aggregates monthly rent collection metrics (expected, collected, outstanding, collection rate) across the user's properties.
